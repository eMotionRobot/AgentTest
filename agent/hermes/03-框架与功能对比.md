# 框架与功能对比：Hermes Agent vs OpenClaw

> 本文从设计哲学、架构、功能矩阵、性能/部署/生态等维度做横向对比，并给出选型建议。
> 三专题（技能进化 / 记忆优化 / 多 Agent）的细节见 [04](./04-skill技能进化.md)、[05](./05-记忆优化.md)、[06](./06-多agent架构.md)。

---

## 1. 设计哲学对比

| | Hermes Agent | OpenClaw |
|---|---|---|
| 核心隐喻 | **自我进化的智能体**（agent that grows with you） | **网关即平台**（gateway as control plane） |
| 中心抽象 | `AIAgent` 对话循环 + 学习闭环 | `Gateway` 控制面 + Agentic Loop |
| 学习方式 | 系统级自动闭环（后台复盘 + Curator） | 用户手动维护（编辑 Markdown / 安装技能） |
| 控制取向 | 默认更"安全 + 自动"，越用越懂你 | 默认更"手动 + 透明"，工作区原生 |
| 出品背景 | 研究机构（Nous Research），含训练数据管线 | 个人开发者 + 庞大社区，产品化/生态化 |

两篇深度对比文章给出的共识可转述为：Hermes 更适合"想要更安全、长期运行、随使用而复利成长"的场景；OpenClaw 更适合"想要更紧的手动控制、工作区原生助理模型"的场景（[turingpost](https://www.turingpost.com/p/hermes)、[trilogyai](https://trilogyai.substack.com/p/technical-deep-dive-hermes-vs-openclaw)，内容经转述）。

## 2. 技术栈与架构

| 维度 | Hermes Agent | OpenClaw |
|------|--------------|----------|
| 主语言 | Python（后端）+ TS/React-Ink（TUI） | Node.js / TypeScript |
| 进程模型 | Python 核心 + Ink 前端，stdio JSON-RPC | 常驻 Gateway 守护进程 + Agent Runtime |
| 配置方式 | `~/.hermes/config.yaml` + `.env`（密钥） | `~/.openclaw/openclaw.json` + 工作区 Markdown |
| 人格/指令文件 | 系统提示 + 技能 + MEMORY/USER.md | `SOUL.md` / `AGENTS.md` / `TOOLS.md` |
| 扩展机制 | 插件（钩子/工具/CLI）+ MCP | 工具/技能/扩展 + MCP |
| IDE 集成 | ACP（VS Code / Zed / JetBrains） | 以渠道/节点为主 |

## 3. 功能矩阵（详细）

| 功能 | Hermes Agent | OpenClaw |
|------|:---:|:---:|
| **技能自动创建** | ✅ 复杂任务后自动沉淀 | ⚠️ 主要人工编写 |
| **技能使用中自改进** | ✅ | ❌ |
| **技能后台生命周期管理（Curator）** | ✅ 置顶/归档/合并/补丁 | ❌ |
| **技能注册中心 / 标准** | agentskills.io 兼容 | ClawHub |
| **持久记忆** | MEMORY.md + USER.md（冻结快照） | SOUL.md + MEMORY.md |
| **可插拔记忆后端** | ✅ honcho/mem0/supermemory… | ⚠️ 以文件为主 |
| **跨会话全文检索** | ✅ SQLite FTS5 + 三元组（CJK） | ⚠️ 会话历史，无内建 FTS |
| **辩证式用户建模** | ✅ Honcho | ❌ |
| **上下文压缩** | ✅ 辅助模型摘要 + 头尾保护 | ✅ `/compact` |
| **子代理 / 并行** | ✅ delegate（批量并行） | ✅ `sessions_spawn` |
| **多 Agent 编排** | ✅ Kanban 看板 | ✅ 渠道→隔离 Agent 路由 |
| **多模型协作** | ✅ Mixture-of-Agents | ⚠️ 模型失败回退为主 |
| **消息渠道数** | ~10+ | **20+** |
| **移动端 / 设备节点** | ⚠️ 以消息端为主 | ✅ macOS/iOS/Android Node |
| **语音唤醒 / 实时 Canvas** | ⚠️ 语音转写 | ✅ Voice Wake + Live Canvas |
| **定时/自动化** | ✅ Cron | ✅ Cron + Heartbeat + 事件钩子 + 常驻指令 |
| **终端后端** | **6 种**（含 Modal/Daytona Serverless） | Docker/SSH/OpenShell（侧重沙箱） |
| **Serverless 持久化** | ✅ Modal/Daytona | ⚠️ |
| **模型供应** | 300+（一键切换） | 可插拔（OpenAI OAuth 等） |
| **MCP** | ✅ 一等公民 | ✅ |
| **迁移工具** | ✅ `hermes claw migrate` 从 OpenClaw 导入 | — |
| **社区规模** | 成长中 | 200k+ stars，生态成熟 |

> 标注为相对评估；以各项目最新版本为准。

## 4. 安全模型对比

| | Hermes Agent | OpenClaw |
|---|---|---|
| 命令审批 | ✅ 命令审批 / 允许列表 | ✅ 允许列表 |
| DM 配对 | ✅ | ✅ pairing |
| 容器隔离 | ✅ docker/singularity 等多后端 | ✅ `sandbox.mode=non-main`（Docker/SSH/OpenShell） |
| 默认姿态 | 偏"安全默认" | `main` 会话默认在宿主机全权运行（仅你自己时） |
| 供应链 | 依赖强制上界版本锁定（litellm/蠕虫事件后强化） | 常规依赖管理 |

两者都强调"入站 DM 视为不可信"，但 Hermes 在依赖供应链与默认安全姿态上着墨更多；OpenClaw 在单用户场景默认给 `main` 会话宿主机全权，强调暴露到公网前先读安全 runbook。

## 5. 性能与资源

- 多篇评测转述称：在相同模型下，**Hermes 比 OpenClaw 更快、更轻量**（[popularaitools](https://popularaitools.ai/blog/hermes-agent-vs-openclaw)，内容经转述）。
- Hermes 可在 5 美元 VPS、GPU 集群或 Serverless（闲置近零成本）上运行；OpenClaw 推荐 Node 24，作为常驻守护进程在本地/服务器运行。
- 记忆稳健性：有评测转述指出 OpenClaw 偶有"忘记上下文"的反馈，而 Hermes 的自学习技能系统默认留存更好（[kilo.ai](https://kilo.ai/kiloclaw/openclaw-vs-hermes)，内容经转述）。此类主观评测仅供参考。

---

## 6. 互操作：Hermes 可从 OpenClaw 迁移

Hermes 内建 `hermes claw migrate`，可自动检测 `~/.openclaw` 并导入：
- `SOUL.md`（人格）、`MEMORY.md`/`USER.md`（记忆）、用户技能（→ `~/.hermes/skills/openclaw-imports/`）、命令允许列表、消息平台配置、白名单 API 密钥、TTS 资源、`AGENTS.md` 工作区指令。

支持 `--dry-run` 预览、`--preset user-data`（不含密钥）、`--overwrite` 等。社区还有 `HermesClaw` 桥接，让两者在同一微信账号上并存。这从侧面说明：**二者定位相近、可平滑过渡，甚至可组合使用**。

## 7. 选型建议

**选 Hermes Agent，如果你：**
- 想要一个**越用越懂你**、能自动沉淀经验与技能的长期智能体；
- 需要**跨会话检索**历史、可插拔记忆后端、辩证式用户建模；
- 计划在 **Serverless / 云 VM / 集群**上长期低成本运行；
- 重视 MCP、IDE（ACP）集成，或需要批量轨迹用于模型训练；
- 偏好更安全的默认姿态与依赖供应链治理。

**选 OpenClaw，如果你：**
- 想要一个**渠道丰富、移动端/语音/Canvas 多模态**的个人助理；
- 偏好**网关优先、工作区原生**、纯 Markdown 透明配置与**更紧的手动控制**；
- 看重**成熟生态**（200k+ stars、ClawHub、SOUL.md 模板库）；
- 主要在本地/单用户场景使用，愿意自己维护技能与记忆。

**两者皆可 / 组合使用：**
- 多篇文章建议"不必二选一"——可同时使用，甚至通过桥接共享同一账号；
- 从 OpenClaw 起步、再用 `hermes claw migrate` 迁移到 Hermes，是一条低摩擦路径。
